# 数据库学习路线（写给学过一点 MySQL 的你）

> 结论先说：**你的 MySQL 底子，90% 直接能用。** 下面第一节就是「哪些不用重学」。
> 真正需要补的，是「表怎么设计」和「后端怎么安全地读写」这两件事，
> 而这正好能拿你自己的小站当练习场。

---

## 一、先放心：这些你已经会的，这里一模一样

`db/schema.sql` 开头写了对照表，这里展开说：

| 你会的（MySQL） | 这里（SQLite） | 要改吗 |
|---|---|---|
| `CREATE TABLE` 建表 | 一样 | 不用改 |
| `INSERT INTO t (a,b) VALUES (?,?)` | 一样 | 不用改 |
| `SELECT ... FROM ... WHERE ...` | 一样 | 不用改 |
| `UPDATE ... SET ... WHERE ...` | 一样 | 不用改 |
| `DELETE FROM ... WHERE ...` | 一样 | 不用改 |
| `ORDER BY` / `LIMIT` / `OFFSET` | 一样 | 不用改 |
| `COUNT` / `SUM` / `MAX` / `AVG` | 一样 | 不用改 |
| `GROUP BY` / `HAVING` | 一样 | 不用改 |
| `LIKE '%关键词%'` 模糊查询 | 一样 | 不用改 |
| `DISTINCT` 去重 | 一样 | 不用改 |
| 主键 / 唯一约束 / 索引 | 一样 | 不用改 |
| `AUTO_INCREMENT` | `AUTOINCREMENT` | 少一个下划线，写法略微不同 |
| `VARCHAR(200)` `INT` `DATETIME` | 只有 `TEXT` `INTEGER` `REAL` | **更简单**：不用纠结字段长度了 |
| `NOW()` | `datetime('now','localtime')` | 换个写法 |
| `LEFT JOIN` 连表 | 一样 | 不用改 |

**所以第一件该做的事：别把时间花在重学语法上。**

## 二、SQLite 和 MySQL 的差别（知道这几点就够）

说实话差别不在语法，在这几件事上：

| | SQLite（这里用的） | MySQL |
|---|---|---|
| 形态 | **一个文件**，`db/site.db` | 一个服务，要先启动、配账号密码、连端口 |
| 备份 | 复制那个文件 | `mysqldump` 导出 |
| 同时很多人在写 | 会排队，不太擅长 | 擅长 |
| 数据类型 | 只有 5 种，宽松 | 很多种，严格 |
| 适合 | 个人站、小工具、本地应用、手机 App | 网站后台、多人协作系统 |

一句话总结：**SQLite 是「够用就好」，MySQL 是「扛得住人多」。**
你这个个人站，永远用不到 MySQL 那部分能力。

## 四、分阶段该学什么

### 阶段 ①　把已会的用熟（现在就能做，约 1~2 周）

不用学新东西，就是把你知道的 SQL 用到这个站上。

**练习（都在 `db/README.md` 第四节，可以直接抄）：**

- 按分类统计每类几篇文章 → `GROUP BY`
- 找出标题或正文含某个词的 → `LIKE` + `OR`
- 技能表按进度排序 → `ORDER BY`
- 统计「掌握 / 在学 / 计划」各几条 → `GROUP BY` + `COUNT`

**这一步的目标**：看着你自己写的 10 篇文章，能随手写出 SQL 把它们查出来。
这种「我有个问题 → 我能用 SQL 问出答案」的感觉，比背语法重要得多。

**要补的知识点**（如果哪个卡住了再去查）：

- `WHERE` 里 `AND` / `OR` 的优先级（`OR` 条件一定要加括号，这是个经典坑）
- `GROUP BY` 和 `HAVING` 的区别（`WHERE` 筛行，`HAVING` 筛组）
- `NULL` 不等于任何值，判断要用 `IS NULL` 而不是 `= NULL`
- `LIMIT 10 OFFSET 20` 是怎么实现翻页的

### 阶段 ②　表怎么设计（这是你真正要补的，约 2~3 周）

你自己的技能表里写着「数据库（MySQL）—— 想先把『表要怎么设计』这件事弄清楚」。
说得对，这才是核心。语法半个月就会，设计要靠积累。

**核心就三个概念：**

1. **主键（PRIMARY KEY）** —— 每一行唯一的名字。
   看 `schema.sql` 里的 `id INTEGER PRIMARY KEY AUTOINCREMENT`。
2. **外键（FOREIGN KEY）** —— 指向另一张表的主键，表示「这两条数据有关系」。
3. **一对多 / 多对多** —— 一篇文章有多个标签，一个标签属于多篇文章 = 多对多，
   这时候要加一张「中间表」。

**你自己的库现在有个「简化」的地方，正好当教材：**

`articles.tags` 存的是 `'博客,更新,整理'` 这样一个逗号串。
现在够用，但它有个代价 —— 想查「所有带 音乐 标签的文章」只能：

```sql
SELECT * FROM articles WHERE tags LIKE '%音乐%';
```

这有两个问题：
1. **慢**：`LIKE '%x%'` 用不上索引，每行都要扫一遍。
2. **会误伤**：如果以后有个标签叫「音乐史」，搜「音乐」会把它一起搜出来。

**规范化之后应该长这样（三张表）：**

```
articles (id, title, ...)          文章
tags     (id, name)                标签
article_tags (article_id, tag_id)  中间表：哪篇文章有哪个标签
```

查「带音乐标签的文章」就变成：

```sql
SELECT a.* FROM articles a
  JOIN article_tags at ON at.article_id = a.id
  JOIN tags t ON t.id = at.tag_id
WHERE t.name = '音乐';
```

**练习建议**：先不要动现在的代码（现在这样跑得好好的），
而是在数据库里**新建这三张表**（叫 `tags2` / `article_tags2` 之类），
把现有的 10 篇文章的标签手工导进去，然后用 `JOIN` 把结果查出来
和 `LIKE` 的结果对比一下。等你觉得「确实更清楚」了，再考虑改代码。

> 这一步能练到的关键字：`JOIN`（连表）、`ON`（连的条件）、
> `PRIMARY KEY`、`FOREIGN KEY`、`UNIQUE`（唯一约束）、`INDEX`（索引）。

**推荐的入门材料**：SQLBolt（sqlbolt.com，英文但很直观，一关一关过）、
《SQL 必知必会》第 2 章「检索数据」到第 13 章「创建高级联结」。

### 阶段 ③　后端怎么安全地读写（约 1~2 周）

这部分你**现在就能看实物** —— `server.js` 里全写着。

**三个必须懂的：**

1. **参数化查询（`?` 占位符）—— 防 SQL 注入**

   看 `server.js` 里所有 SQL 都长这样：

   ```js
   db.prepare('SELECT * FROM articles WHERE id = ?').get(id)
   ```

   那个 `?` 就是占位符，值是通过参数传进去的，**不拼字符串**。
   如果写成 `'... WHERE id = ' + id`，别人把 id 填成
   `1 OR 1=1` 就能把你的数据全捞走。这是最经典的漏洞，务必养成习惯。

   想亲眼看看它长什么样，可以专门写一个拼接字符串的版本试试 —— 
   **只在你本地的测试库上试，别在真的站上试。**

2. **事务（`BEGIN` / `COMMIT` / `ROLLBACK`）**

   看 `db/seed.js` 和 `server.js` 里的 `PUT /api/skills`：

   ```js
   db.exec('BEGIN');
   try {
     // 先全删，再全插
     db.exec('COMMIT');
   } catch (e) {
     db.exec('ROLLBACK');   // 中途出错就整个撤销
     throw e;
   }
   ```

   用途：一组操作「要么全成功，要么全不动」。
   比如整张技能表替换，如果删完了插入时崩了，没事务的话表就空了。

3. **一个查询够不够（N+1 问题）**

   你现在写 `GET /api/profile` 是：查一次 profile，再查一次 skills。
   两次查询，没问题。
   但如果「查 10 篇文章，每篇再查一次作者」，那就变成 1 + 10 = 11 次 —— 
   这叫 N+1，数据一多就很慢。解决办法是用 `JOIN` 一次查出来。

**练习建议**：给现在的项目加一个「文章浏览计数」——
在 `articles` 表加一列 `views INTEGER DEFAULT 0`，
加一个 `POST /api/articles/:id/view` 接口，每次打开文章 `views = views + 1`。
这个练习很小，但把「改表结构 → 改接口 → 改前端」整条路走了一遍。

> ⚠️ 改 `schema.sql` 之后**不要**跑 `node db/seed.js --reset`（会清空数据）。
> 正确做法是写一条 `ALTER TABLE`：
> `ALTER TABLE articles ADD COLUMN views INTEGER DEFAULT 0;`
> —— 这就是「数据库迁移」的雏形，是很重要的一个概念。

### 阶段 ④　以后再说的（不着急）

- **索引到底怎么用**：`EXPLAIN` 看查询计划，知道什么时候该加索引
- **备份与恢复**：SQLite 就是复制文件；MySQL 用 `mysqldump`
- **连接池**：为什么不能每个请求都新开一个连接
- **ORM**：像是 Prisma / Sequelize 这类工具，用代码代替手写 SQL 的取舍
- **NoSQL**：什么时候该用，什么时候不该用

## 五、给你的一句话建议

你的项目已经是个很不错的练习场了 —— 它够小（不至于被复杂度淹没），
又够真（有增删改查、有表关联的苗头、有前端后端）。

**别去找「数据库教程」从头啃。** 就在这个小站上，每次想加一个小功能，
先问自己：「这个数据该长什么样？」然后去改表、写 SQL、改接口。
做三五次，你对「表设计」的感觉就有了。

真卡住的时候，`db/README.md` 第四节那几条 SQL 可以直接抄来改。
