# 朔的小窝 · Shuoscape

一个自己手写的个人小站。纯 HTML / CSS / JavaScript，**零第三方依赖**
（用的是 Node.js 自己带的网页服务和数据库模块，不用 `npm install` 装任何东西）。

---

## 一、怎么跑起来

### 准备工作（只需一次）

装一个 **Node.js 22.5 或更新的版本**：去 <https://nodejs.org/> 下载 LTS 版安装即可。

> 为什么要 22.5+？因为要用 Node 自带的数据库模块（`node:sqlite`）。
> 装成老版本（18 / 20）启动时会提示你，不会报一堆看不懂的错。

### 启动（以后每次都这样）

**双击 `start.bat`** 就行。

它会：（第一次）自动建好数据库 → 启动网站 → 帮你打开浏览器。
关掉那个黑窗口，或者在里面按 `Ctrl + C`，就是停止服务。

喜欢敲命令的话：

```bash
node server.js             # 启动网站，浏览器打开 http://localhost:5173
node server.js --no-open   # 启动但不要自动打开浏览器
node db/seed.js            # 只建库（已有数据会跳过）
node db/sync-music.js      # 只把 data.js 的歌单同步进数据库（别的表不动）
node db/seed.js --reset    # 清空重来，恢复初始数据（会连文章一起清掉，慎用）
```

端口 5173 被占用时会自动往后试 5174、5175……

## 二、两种打开方式（这是这个站的一个特点）

这个方法有点特别：**同一套网页，用两种方式打开都行，用起来都一样。**

| | 数据库模式（推荐） | 本地模式 |
|---|---|---|
| 怎么打开 | 双击 `start.bat`，走 `http://localhost:5173` | 直接双击 `index.html` |
| 数据存在哪 | `db/site.db` 数据库文件 | 浏览器自己的存储里 |
| 换浏览器还在吗 | 在 | 不在 |
| 能用 VS Code 看数据吗 | 能 | 不能 |
| 需要启动什么吗 | 需要跑 `start.bat` | 什么都不用 |

打开网页时它会自动探测一下「有没有后端」，然后挑一套用。
**判断方法**：看页脚右下角那行字，会多一个小小的标记 ——
绿色的「数据库」或者灰色的「本地」。鼠标放上去还有一句解释。

也就是说：

- 你想随便打开看看 → 双击 `index.html` 就行
- 你想真的往里写东西 → 双击 `start.bat`

## 三点五、登录：管理员 / 未登录

- **不登录** → 只能看，全站的「编辑 / 删除 / 新增」按钮都收着。
- **管理员登录**（页面最上面那条身份条，或关于页点头像、右上角「未登录」徽章）→ 能改内容。

密码**不在源码里**。流程是：网页把账号密码 `POST /api/session` 交给 server.js 核对，
通过才发一张临时凭证（12 小时有效），之后每个写请求都带上它。

- 密码看哪里：**启动服务那个黑窗口**会打印一行「管理员密码 xxx」。
- 想换成自己的：设环境变量 `ADMIN_PASSWORD`，或者改 `db/admin.secret` 里那一行。
- `db/admin.secret` 已写进 `.gitignore`，不会跟着提交。
- 登录状态记在浏览器里，关掉再开还在；点身份条上的「退出登录」就失效。

⚠️ **没有跑 server.js 时登录不了**（本地双击 html、或 GitHub Pages 这种纯静态托管）——
没有服务器就没人能核对密码，登录框会直接这么告诉你。

**写接口是有鉴权的**：除了 `GET`、`/api/session` 和「游客留言 POST」，
其余 POST / PUT / DELETE 都必须带请求头 `X-Admin-Token`，否则返回 403。
静态 Token 用环境变量 `ADMIN_TOKEN` 设置（不设就用内置默认值，启动时会打警告）。

## 五、常见问题

**Q：双击 `start.bat` 一闪就没了？**
说明没装 Node.js，或者版本太旧。窗口里会有一行提示。去 <https://nodejs.org/> 装 LTS 版。

**Q：`node server.js` 报 `Cannot find module 'node:sqlite'`？**
Node 版本低于 22.5。装新版。

**Q：改了网页代码看不到变化？**
刷新就行（服务设了不缓存）。改了 `server.js` 要重启（关掉黑窗口再双击 `start.bat`）。

**Q：不小心删了东西怎么恢复？**
数据库里删掉就是真的没了。所以重要内容建议定期把 `db/site.db` 复制一份存起来
（**复制这一个文件 = 完整备份**，这是 SQLite 最大的好处）。
如果只是想回到最初的示例内容，跑 `node db/seed.js --reset`（会清空现有内容）。

**Q：想换个端口？**
`set PORT=3000 && node server.js`（Windows cmd），或者改 `server.js` 里的 `START_PORT`。

**Q：后来又加了新字段，我数据库里的内容会不会被清掉？**
不会。加字段用的是 `ALTER TABLE ... ADD COLUMN`，只往表上加一列，
已有的行一行都不动。这段逻辑写在 `server.js` 的 `MIGRATIONS` 里，
**每次启动都会检查一遍**：没有那一列才加，已经有了就跳过。
所以你在界面上写的文章、小诗、唱片都安全。

> 这一类操作叫**数据库迁移**。它和 MySQL 的关系：
> SQLite 的 `PRAGMA table_info(表名)` 相当于 MySQL 的 `SHOW COLUMNS FROM 表名`；
> `ALTER TABLE` 两边也差不多，只是 SQLite 一次只能加一列，
> 而且不能加「NOT NULL 又没有默认值」的列。
>
> 特别提醒：加字段**不要**用 `node db/seed.js --reset` —— 那是清空重建，
> 你写的内容会一起没掉。换歌单用 `node db/sync-music.js`，加字段靠上面的迁移。

**Q：音乐点了播放没声音？**
碟架和唱片机下面都会标出原因：

- 显示**「待放文件」** → 这个文件还没放进 `assets/audio/`。
  放进对应名字的文件就会变成绿色的「本地有声」，不用改任何代码
  （放法见下面的「音乐」一节，或 `assets/audio/README.txt`）。
- 显示**「本地有声」**但还是没声音 → 检查一下浏览器是不是静音了。

**后缀不用和配置一致**：`js/data.js` 里六首统一写的是 `.mp3`，
你实际放 `Echoes.m4a` / `.ogg` / `.wav` / `.flac` 也能被认出来 ——
代码会按 `mp3 → m4a → ogg → wav → flac → aac → opus` 的顺序挨个试。
后缀和配置不一样时，唱片机下面会直接告诉你实际用的是哪个文件。

> ⚠ **音乐软件下载的加密文件放不出来。**
> QQ音乐的 `.mgg` / `.mflac` / `.qmc0`、网易云的 `.ncm`、酷狗的 `.kgm`、
> 酷我的 `.kwm` 都是加密格式，只有各家自己的播放器能解，浏览器读不懂。
> 这是格式问题，不是路径配错了，本站也不做解密，
> 请通过正规途径拿普通格式的文件（`assets/audio/README.txt` 里有详细说明）。

## 六、音乐：分类与本地音频

**碟架按分类分组。** 每张碟都有一个「分类」（民谣 / 摇滚 / 影视原声……），
同类的歌摆在一组里，组头上写着分类名和歌曲数。分类是在每张碟的「✎」里填的，
想改随时改；没填的会归进最后一组「未分类」，不会丢。

**mp3 的两种放法（都能被认出来）：**

```
① 平铺（最省事）
   assets/audio/Echoes.mp3

② 按分类分文件夹（歌多了以后好找）
   assets/audio/氛围/Echoes.mp3
   assets/audio/民谣/Far From Home.mp3
```

程序会先找平铺的、再找分类文件夹里的；按歌手建文件夹
（`assets/audio/梁博/Echoes.mp3`）也一样认。
文件名对得上就自动生效，**不用改任何配置**。

> **这个功能是怎么实现的？** 探测文件用的是 `<audio>` 元素能不能读出元数据
> （`file://` 下脚本读不了目录，所以没法扫描文件夹，只能拿「分类名」「歌手名」
> 当候选目录名去试）。想看代码就搜 `js/music.js` 里的 `audioCandidates()`。

**音乐没有单独的页面了**：整台唱片机（黑胶、进度条、碟架）就在
**首页底部「曲音拾集」** 区块（`index.html#music`）。
想直接分享某一首歌，用形如 `index.html?id=3#music` 的网址打开，
它会自动选中那一首。

> 这六首都是有版权的商业歌曲，本站不提供下载，也不解密任何加密格式。
> 想离线听，请用你自己合法拿到的文件。

## 七、学习页：C 语言 + 英语

**C 语言**分两层：

- **学习页上的知识点清单**（study.html）：28 个小目标按 7 组摆好，
  会一条勾一条，勾过的会划掉。打卡记录存在浏览器里，不进数据库 ——
  课程是大家的，进度是你自己的。
- **完整练习站**（`c/` 目录）：你原来单独做的那套整个搬了进来，
  知识点讲解、515 道章节练习、32 套真题卷共 1517 题原样都在，
  品牌色换成了主站的粉紫、导航和页脚也换成了主站的
  （适配全在 `c/css/bridge.css`，那套页面自己的代码一行没动）。
  真题卷是卷面扫描图（559 张 PNG，共 77MB），已经随站一起打包，
  部署到 GitHub Pages 后线上也能直接翻看。

**英语 · 词汇复习**（`english.html`，从学习页「英语」区进入）三个板块：

- **词汇复习**：三块统计（词库总量 / 待巩固错题 / 今日已练习），勾选若干份资料，
  选英译汉 / 汉译英 / 混合、题量和随机顺序，开始练习；
  打错了（或看答案、跳过）按翻译方向自动记入错题本，重新答对自动归入已掌握；
  一轮没练完会记住，下次打开能接着练。
- **我的错题本**：待巩固 / 已掌握 / 全部记录三个页签，可按关键词和方向筛选，
  能手动「标记掌握」或「恢复待巩固」，也能一键「重练错题」。
- **学习资料**：导入 `.docx` / `.pdf`（需要可选择文字）/ `.txt` / `.md` 词库，
  每行一个词（`英文 中文`、`英文=中文`、`英文：中文`、表格两列、两格以上空格都认）；
  导入后先核对再保存，能查看、编辑、删除；支持「导出学习备份 / 恢复备份」。

资料和练习记录都保存在**当前浏览器**（IndexedDB）里，换设备前先导出备份。
管理员在「学习资料」里勾选「共享给所有人」上传的资料会存到云端，
所有访客都能看到，且每 3 分钟自动检查一次更新。
导入 / 编辑 / 删除资料要管理员登录；练习、标掌握不用。

> 词库解析格式在 `js/english.js` 的 `EnParse.parseLine()` ——
> 以后有固定模板（Word / PDF 长什么样定下来），改这一个函数就能对上。
> .docx 是在浏览器里直接解压读的（`DecompressionStream`，不用联网）；
> .pdf 用 pdf.js —— 已经下好放在 `vendor/` 里，**离线也能用**；那份万一没跟着上传，会自动改从 CDN 拉。

### 导入认什么格式

最常见的讲义排版直接认：

```
1. be known as 被称为；以……而闻名
39. give sb. some advice about doing sth.给某人一些关于做某事的建议
```

英文和中文之间**有空格 / 没空格 / 用 = / 用冒号**都行 —— 靠「第一个汉字在哪」切分；
中文写前面（`放弃 abandon`）也能认。页眉、水印这类干扰词（如「小蓝人」「内部资料」）
会自动忽略，还能在导入框的「要忽略的字」里自己加。认完先进核对表，能改能删再保存。


## 留言板（评论）

文章和每条小诗下面都有「留言」区：填个名字（不填就是匿名）写两句，点「留言」就发出去。

- **填了云端配置（推荐，见下）**：留言进云端数据库 —— 任何人打开这个网站看到的都是同一批留言，**传到 GitHub Pages 上也是**。
- **跑着 server.js 时**：留言进数据库 `comments` 表，存服务器上 —— 换浏览器、别人访问，看到的都是同一批。
- **直接双击 html（本地模式）**：留言退回浏览器 localStorage，只留在这台设备上，页面底部会写明白。
- 管理员登录后，鼠标移到留言上会出现 ✕，可以删掉不合时宜的。
- 接口：`GET/POST /api/comments`、`DELETE /api/comments/:id`（名字限 24 字、正文限 1000 字）。

### 让留言「上传 GitHub 后人人可见」：两分钟配一次

GitHub Pages 是纯静态的，本身没有后端，所以要用一个免费的云端数据库（Supabase）：

1. 打开 `supabase.com`，用 GitHub 账号登录 → New project（免费，地区选 Singapore / Tokyo）。
2. 建好后：**Settings → API**，把 `Project URL` 和 `anon public key` 填进 `js/config.js`
   —— 只想让留言上云就填 `comments` 那一块，**想把文章/小诗/唱片/资料也一起搬上云就把 `content` 那块也填了**（见下面「开启内容上云」）。
3. **SQL Editor** → 把项目里的 `supabase.sql` 整段粘进去 → Run。
4. 提交到 GitHub。搞定 —— 之后谁打开你的 Pages 网站，留言都是同一批；
   自己在本地跑 server.js 发的留言，也会进同一个云端库。

没填这两项时一切照旧（本地 / 数据库模式），不会报错。

## 部署到 GitHub Pages（静态站）

1. 把整个 `my-site` 目录推到 GitHub 仓库（`db/site.db`、`db/admin.secret`、`_bak/` 已写进 `.gitignore`，不会推上去）。
2. 仓库 **Settings → Pages → Source** 选 `main` 分支根目录 → Save。
3. 等一两分钟，访问 `https://<你的用户名>.github.io/<仓库名>/`。

Pages 是纯静态托管，**不运行 server.js**，所以：

- 没做下面的「内容上云」时，Pages 上看到的是仓库里那份 `js/data.js` 的初始数据，管理员登录用不了。
- 做了「内容上云」之后，Pages 上读的是云端数据，用邮箱密码登录后能增删改。

## 开启内容上云（可选，推荐）

做完这七步，你的网站就变成「**访客读云端数据，你登录后改，所有人刷新看到的都是同一版**」：

1. 打开 `supabase.com` → New project（免费，地区选 Singapore / Tokyo）。
2. **Settings → API**，记下 `Project URL` 和 `anon public key`。
3. **SQL Editor** → 把项目里的 `supabase.sql` 整段粘进去 → Run（建 7 张表 + 访问策略）。
4. **Authentication → Users → Add user**，创建你自己的管理员邮箱和密码
   （这就是以后登录用的账号，前端代码里一个账号密码都没有）。
5. 修改 `js/config.js`：把 `Project URL` / `anon key` 填进 `content` 和 `comments` 两块
   （两块都填：一块管内容，一块管留言）。
6. 迁移本机数据 —— 在 `my-site` 目录执行：

   ```
   node db/export-to-supabase.js --url <Project URL> --key <service_role key>
   ```

   `service_role key` 在 **Settings → API → service_role**，是「超级钥匙」，
   **只在本机跑这个脚本时用，绝不能写进前端代码、也别推到 GitHub**。用完可以在后台 Rotate 换一把。
   脚本可重复执行（每张表先清空再写入），不会产生重复数据。
7. 重新 push，刷新线上页面 —— 访客看到云端数据；你用邮箱密码登录后即可增删改。

### 上云后的三种模式怎么自动切换

| 情况 | 模式 | 数据从哪来 | 能改内容吗 |
|---|---|---|---|
| `js/config.js` 填了 Supabase | `cloud` | 云端数据库 | 用 Supabase 邮箱密码登录后可增删改 |
| 没填配置 + 跑着 `server.js` | `db` | `db/site.db` | 用 server.js 打印的账号密码登录后可增删改 |
| 没填配置 + 双击 html | `local` | `data.js` + 浏览器 localStorage | 不能（没有服务端能核对密码） |

判断逻辑写在 `js/data.js` 的 `SiteAPI.whenReady()` 里：云端优先，其次探 `/api/health`，都没有就退回本地。
页面代码一行都不用改 —— 三种模式的读写方法签名完全一致。

### 安全说明

- 前端只有 `anon public key`，它本来就会出现在网页源码里，**只能读**；真正拦住乱写的是 `supabase.sql` 里的 RLS 策略（写操作一律要求 `auth.role() = 'authenticated'`）。
- 留言表是「公开读、公开写、不公开删」—— 想删留言去后台 Table Editor 手动删，网页上的 ✕ 会提示你去后台。
- 源码里搜不到任何 `service_role key`，它只在 `db/export-to-supabase.js` 被调用时由你在命令行传入。
